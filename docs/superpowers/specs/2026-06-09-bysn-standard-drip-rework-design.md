# BYSN Standard Drip 作り替え 設計書

- 作成日: 2026-06-09
- 対象: ドリップガイドの「BYSN Standard Drip」レシピ
- 公式レシピ出典: `docs/guides/coffee-brewing-guide.md`（現場の紙レシピ表の文字起こし）

## 目的

「BYSN Standard Drip」を、公式レシピ（`coffee-brewing-guide.md`）に完全準拠させる。具体的には次の2つを満たす。

1. **人数スケーリングを公式早見表どおりにする**（現状は線形倍率で3人前以上の粉量がズレる）
2. **抽出前の準備手順をガイドに加える**（ペーパーのセット・ドリッパーの温め・粉のならし方）

## 背景・現状分析

### 数値はすでに一致している（注湯量・蒸らし時間）

公式「基本レシピ(2人分)」を1人前に割ると、現行の `mockData.ts` の BYSN（1人前基準）と一致する。

- 公式2人分: 粉20g・蒸らし20g・注湯 180→80→40
- 1人前換算: 粉10g・蒸らし10g・注湯 90→40→20
- 現行実装(1人前基準): 蒸らし10g → 累計100(+90) → 累計140(+40) → 累計160(+20) → 落ち切り

→ **注湯量・蒸らしは公式どおり**。早見表の1人前(90/40/20)とも一致。

### 問題：人数スケーリングが線形

`lib/drip-guide/recipeCalculator.ts` は `multiplier = servings` で全項目を一律に倍する。
公式早見表は**粉量だけが非線形**（人数が増えると1杯あたりの粉が減る＝過抽出を避ける現場調整値）。

| 人数 | 公式 粉量 | 現行(×人数) | 差 |
|---|---|---|---|
| 1人前 | 10g | 10g | 0 |
| 2人前 | 20g | 20g | 0 |
| 3人前 | **25g** | 30g | +5g |
| 4人前 | 35g | 40g | +5g |
| 5人前 | 40g | 50g | +10g |
| 6人前 | 45g | 60g | +15g |
| 7人前 | 50g | 70g | +20g |
| 8人前 | 55g | 80g | +25g |

一方、3投の注湯量（90/40/20×人数）は**線形で公式と一致**（早見表の各列は 90n / 40n / 20n / 完成140n と完全に線形）。
非線形なのは**粉量のみ**で、それに連動する**蒸らし湯（=粉量）**が従属的にズレるだけ。

### 他レシピの調査結果（スコープ確定の根拠）

公式の人数別早見表を持つのは BYSN だけ。

- **4:6メソッド（粕谷哲）**: 比率メソッド（粉×15＝湯）。公式に人数別テーブルは無く、比率を保つ＝線形。
- **井崎流（井崎英典）**: 比率メソッド（湯100gあたり粉6〜8g）。公式に人数別テーブルは無い。
- 一般原則（UCC解説）: 2杯までは倍量でOK、4杯以上は粉を減らすと良い——ただしこれは一般論で、4:6/井崎流の**公式数値ではない**。

結論: 4:6・井崎流に非線形テーブルを作るのは根拠のない数値の捏造になる。**線形のままが公式に忠実**。よって今回はBYSNだけを直す。

## スコープ

### やること

1. BYSN の人数スケーリングを公式早見表に準拠（粉量＋連動する蒸らし湯＋総湯量）
2. BYSN に抽出前の準備手順（テキスト4ステップ）を追加
3. 関連テスト・ドキュメントの更新

### やらないこと（非スコープ）

- 4:6・井崎流・アイスコーヒーのスケーリング変更（公式が比率＝線形なので据え置き）
- 大人数時の注意書き表示（見送り）
- 準備手順への画像追加（業務PWAでの著作権リスク回避のため今回は見送り。将来 `imageSrc?` 追加で拡張可能）
- 注湯量・蒸らし時間の数値変更（すでに公式と一致）

## 設計①：人数スケーリング修正

### データモデル

`DripRecipe`（`lib/drip-guide/types.ts`）に任意フィールドを1つ追加する。

```ts
export interface DripRecipe {
  // ...既存...
  /** 1人前基準では表せない非線形の粉量を、人数別(1〜8人前)で持つ。
   *  index 0 = 1人前 ... index 7 = 8人前。
   *  指定があるレシピだけ非線形スケーリングを使う。未指定は従来の線形。 */
  beanAmountByServings?: number[];
}
```

BYSN のレシピデータ（`mockData.ts`）に公式早見表の粉量を持たせる。

```ts
beanAmountByServings: [10, 20, 25, 35, 40, 45, 50, 55], // 1〜8人前
```

### 計算ロジック（`recipeCalculator.ts`）

`calculateRecipeForServings` を、`beanAmountByServings` の有無で分岐させる。

- **未指定のレシピ**: 従来どおり線形（`multiplier = servings`）。4:6・井崎流・アイスは挙動不変。
- **指定があるレシピ（BYSN）**:
  - `beans(n) = beanAmountByServings[n - 1]`
  - 蒸らし湯 = 粉量（公式「基本レシピ」で 粉20g＝蒸らし20g、1:1 のルール）
  - **基準湯量 `steepBase = 元のレシピの beanAmountGram`（=1人前の粉量=蒸らし湯。`steps[0]` に依存させない。準備手順を足すと `steps[0]` が蒸らしでなくなるため）**
  - 各ステップの累計注湯: `beans(n) + (元の累計targetTotalWater − steepBase) × n`（`targetTotalWater` 未指定の準備手順は未指定のまま）
    - 蒸らしステップ自身: `beans(n) + 0 = beans(n)`
    - 1投目(元100): `beans(n) + (100 − 10) × n = beans(n) + 90n`
    - 2投目(元140): `beans(n) + 130n`
    - 3投目(元160): `beans(n) + 150n`（160 − 10 = 150。最終注湯ステップなので総湯量と一致する）
  - **総湯量も同式で再計算**: `totalWaterGram = beans(n) + (元totalWaterGram − steepBase) × n = beans(n) + 150n`
    - ※ 一覧の所要時間/湯量表示と各ステップ累計の食い違いを防ぐため、`totalWaterGram` の再計算は必須。
  - `beanAmountGram = beans(n)`

#### 検算（公式表と一致すること）

| n | beans | 蒸らし | 1投累計 | 2投累計 | 3投累計 | 総湯量 | 公式注湯増分 |
|---|---|---|---|---|---|---|---|
| 1 | 10 | 10 | 100 | 140 | 160 | 160 | 90/40/20 ✓ |
| 3 | 25 | 25 | 295 | 415 | 475 | 475 | 270/120/60 ✓ |
| 8 | 55 | 55 | 775 | 1095 | 1255 | 1255 | 720/320/160 ✓ |

注: 公式の「完成量」列(140n)は理想値で、高人数では単純な吸水量計算と完全一致しない。
そのため**蒸らし湯は粉量に直結させる一択**とし、完成量から逆算しない。

## 設計②：準備手順の追加（テキスト）

BYSN（手動モード `isManualMode: true`）の冒頭に、抽出前の準備ステップを4つ追加する。
手動モードは「次へ／前へ」でユーザーが手送りするため、時間が不確定な準備手順をそのまま足せる（新しい仕組み不要）。
準備手順は `targetTotalWater` を持たない＝スケーリング計算の対象外（何人前でも内容不変）。

| 順 | title | description |
|---|---|---|
| 準備1 | お湯を92度に準備 | 温度調節ケトルでお湯を92度に設定します。 |
| 準備2 | ペーパーをセット | 円錐ペーパーの側面の圧着部（縫い目）を折り、ドリッパーにぴったり沿わせます。 |
| 準備3 | ドリッパーを温める | お湯を回しかけてドリッパーとサーバーを温め、ペーパーのにおいを流します。温めると抽出温度が安定します。お湯は捨てます。 |
| 準備4 | 粉をセット | 人数分の粉を入れ、ドリッパーの下部を持って軽く左右に揺らし、表面を平らにならします。 |
| 既存 | 蒸らし → 1投目 → 2投目 → 3投目 → 落ち切り | （変更なし） |

### startTimeSec（ソートキー）の扱い

Runner（`DripGuideRunner.tsx`）は `steps` を `startTimeSec` 昇順でソートして手動インデックスを進める。
準備4ステップは蒸らし(0)より**前に並ぶ値**が必須。0を複数並べると順序不定になるため避ける。

決定: 準備手順に負のソートキーを与える。

- 準備1: `-40` / 準備2: `-30` / 準備3: `-20` / 準備4: `-10`
- 既存の抽出ステップ（蒸らし0 / 1投目20 / 2投目95 / 3投目110 / 落ち切り145）は変更しない。

※ BYSN は手動モードのため `startTimeSec` はソートキーとしてのみ機能し、タイマー進行には使われない（経過時間は実時間で計測）。

### 表示への影響

`FocusGuideDisplay` は `targetTotalWater` 未指定時に湯量ブロックを描かない（既存の `WaterTarget` が null 返し）。
準備手順は湯量を持たないので、説明文中心で正しく表示される。追加改修は不要（実装時に iPad 幅で目視確認する）。

## テスト方針（★は完了ゲート）

- ★ `recipeCalculator.test.ts`:
  - `beanAmountByServings` 分岐を n=1,2,3,8 で検証（粉量・各ステップ累計・総湯量）
  - n=3 で粉25g（旧30gでない）を固定する回帰テスト
  - 「総湯量 == 最終注湯ステップの累計」を検証する不整合検出テスト
  - `beanAmountByServings` 未指定レシピが従来どおり線形であること（非回帰）
- ★ `mockData.test.ts`:
  - BYSN のステップ数増加・準備手順の存在を確認
  - 既存の「最終ステップ開始 < totalDurationSec」（落ち切り145 < 180）が維持されること
