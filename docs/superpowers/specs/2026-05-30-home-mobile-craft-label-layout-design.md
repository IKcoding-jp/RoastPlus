# スマホホーム画面 クラフトラベル型レイアウト 設計書

作成日: 2026-05-30

## 背景と目的

スマホのホーム画面は、以前グリッドから1列の細いリストへ変更した（`docs/superpowers/plans/2026-05-28-home-mobile-list-layout.md`）。
その後、機能を整理して表示項目が減った（PR#463 で5機能削除、現在は全7項目）。
結果、各行の高さが上限 64px で頭打ちになり、実機で「行が小さく、画面下部に余白が残って視認性が悪い」状態になった。

本設計では、スマホのホームを **クラフトラベル型の1列リスト** に再設計する。
ゴールは「**スクロールなしで全項目を1画面に収めつつ、画面の高さを使い切って余白なくまとめ、各行を視認しやすくする**」こと。

## スコープ

### 対象
- スマホ表示（Tailwind の `md` 未満、768px 未満）のホーム画面レイアウト。

### 非対象（変更しない）
- タブレット・PC（`md` 以上）の4列カードグリッド。現状を維持する。
- Firestore、認証、セキュリティルール、機能データ（`lib/homeFeatures.ts` の機能定義）。
- ホーム表示/非表示設定（`useHomeFeatureVisibility`）、アイコン、ナビゲーション、バッジ、クリスマスモード。

## デザイン仕様（クラフトラベル型）

各機能は、コーヒー袋のラベルを思わせる1行のカードとして縦に並べる。

各行の構成（左→右）:
- **アイコン**: 既存の react-icons（線画系）をそのまま使う。
- **英字ラベル**: 小さい大文字・字間広め（tracking）・琥珀アクセント色。機能名の上に置く。
- **機能名**: 大きめの太字。行の主役。
- **シェブロン `›`**: 右端に細く控えめに。

英字ラベル（直訳寄りで確定）:

| 機能 | 英字ラベル |
|---|---|
| 担当表 | ASSIGNMENT |
| スケジュール | SCHEDULE |
| 試飲感想記録 | TASTING |
| 欠点豆図鑑 | DEFECTS |
| 生産記録 | PRODUCTION |
| ドリップガイド | DRIP GUIDE |
| その他 | MORE |

ラベルの質感:
- 角は控えめな角丸（ラベルらしい角張り。現状の `rounded-xl` より小さめ）。
- 紙地の質感は `bg-surface` ＋ `border-edge-strong` ＋ 内側のハイライトで表現する。

### テーマ対応（重要）

配色はハードコードせず、すべて既存テーマトークンで構成する。これにより7テーマ（ライト/ダーク両系統）で破綻しない。

| 用途 | トークン |
|---|---|
| 行の背景 | `surface` |
| 枠線 | `edge-strong` |
| 機能名 | `ink` |
| 英字ラベル / アクセント | `spot` |
| シェブロン | `ink-muted` |
| ホバー背景 | `ground` |
| フォーカスリング | `primary` |

クラフト感は「色」ではなく「形」（小さな字間広めの大文字ラベル、角張った枠、紙地サーフェス、内側ハイライト）で出す。

## レイアウト仕様（高さの埋め方）

### 課題: 1画面充填 と 巨大化防止 の両立

「画面の高さを使い切る」を素朴に実装（各行を一律 `flex-1` で引き伸ばす）すると、
表示項目が1個のとき1行が画面全体を覆う巨大ボタンになる。
これは既存テスト「スマホで表示機能が少ない場合もアクションを巨大化させない」（`app/page.test.tsx`）が守っている要件と衝突する。

### 解決方針: JS高さ計算を廃止し、CSS flexbox に置き換える

現行の `cardHeight` 動的計算（`useEffect` ＋ resize/orientationchange 監視 ＋ CSS変数 `--home-card-height`、上限 64px）を廃止し、CSSの flexbox で表現する。

- スマホのコンテナ: `flex flex-col gap-2`（上詰め）。
- 各行: `flex-1` ＋ `min-h`（タップ領域の下限）＋ `max-h`（巨大化防止の上限）。

挙動:
- **項目が多い（5〜7個・通常ケース）**: 各行が上限未満に収まり、画面の高さを均等に分け合って充填する → 余白が出ない・各行が十分大きい。
- **項目が少ない（1〜2個・稀なケース）**: 各行が `max-h` で頭打ちになり、巨大ボタン化しない（下部に余白は出るが、巨大化防止を優先）。

数値の目安（実装時に実機で微調整可）:
- `min-h`: 約 56px（タップ最小領域を確保）。
- `max-h`: 約 112px（7項目が一般的なスマホ画面で収まる高さを上限とし、少数項目時の巨大化を防ぐ）。

副次効果: `useEffect` ＋ リサイズ/向き監視 ＋ CSS変数 ＋ `cardHeight` の prop 受け渡し、という複雑な仕組みが不要になり、コードが単純化する。

### デスクトップ（md以上）

現状の4列カード（上にアイコン、機能名、説明文）をそのまま維持する。
英字ラベルはスマホ専用とし、`md` 以上では非表示（`md:hidden`）にする。
スマホ専用の `flex-1` / `min-h` / `max-h` は `md` 以上で無効化し、現状のグリッド挙動を保つ。

## 変更ファイル

1. **`app/page.tsx`**
   - `ACTIONS` 配列の各要素に英字ラベル（例: `label: 'ASSIGNMENT'`）を追加。
   - スマホのコンテナを `flex-1` ベースのレイアウトに変更。
   - `cardHeight` の state・`useEffect`（高さ計算とリサイズ/向き監視）・`ActionCard` への `cardHeight` 受け渡しを削除。

2. **`components/home/ActionCard.tsx`**
   - スマホ行をクラフトラベル型（アイコン＋英字ラベル＋機能名＋シェブロン）に変更。
   - 英字ラベルを受け取る prop を追加し、`md:hidden` でスマホ専用表示にする。
   - `flex-1` / `min-h` / `max-h` を付与（`md` 以上では無効化）。
   - `cardHeight` prop と CSS変数 `--home-card-height` への依存を削除。
   - デスクトップのカード表示（アイコン上・機能名・説明文・ホバー演出）は維持。

3. **`app/page.test.tsx`**
   - 巨大化ガードのテスト（現在 `--home-card-height` が `64px` になることを検証）を、新方式に合わせて書き換える。
   - jsdom はflexboxの実レイアウトを計算しないため、px値ではなく「行に巨大化防止の上限（`max-h-*` クラス）が付いている／インライン高さ変数が付かない」ことを検証する方針にする。
   - 既存の表示/非表示テスト（`ドリップガイド`・`その他`）と「機能が1つのアクションとして表示される」テストは維持する。

## 検証方法

- `npm run test:run -- app/page.test.tsx` が通ること。
- `npm run build` が通ること。
- ローカル開発サーバーで、スマホ幅（例: 390×844）のホームを確認:
  - 7項目が1画面にスクロールなしで収まり、画面の高さを使い切って余白が出ないこと。
  - 各行のクラフトラベル表示（英字ラベル＋機能名）が崩れないこと。
  - 表示項目を1個に減らしても巨大ボタンにならないこと。
  - ライト系・ダーク系の複数テーマで配色が破綻しないこと。
- タブレット・PC幅で、4列グリッドが従来どおりであること。

## 実装ガイドライン

- UIスタイル実装時は `/frontend-design` スキルの方針に沿い、汎用的な「AIっぽい」見た目（左の縦アクセントバー＋塗りの丸アイコンなど）を避ける。
- Lint・warning はゼロを維持する。
