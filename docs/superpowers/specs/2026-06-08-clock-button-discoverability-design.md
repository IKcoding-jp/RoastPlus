# 時計ボタンの発見性改善 — 設計

- 日付: 2026-06-08
- 対象: `components/home/HomeHeader.tsx`
- きっかけ: ユーザーから「どうやって時計を開くのか、どこで開けるのか分からない」というフィードバック

## 背景・問題

ホーム画面の各機能（担当表・スケジュール・試飲記録・生産記録・ドリップガイド等）は、
タイトル＋説明文＋アイコンの大きなカードで並んでいる。一方、時計（`/clock`）への入口だけは
ヘッダー右上の小さなゴーストアイコン1つ（ラベルなし）で、背景に溶け込んでいる。

ユーザーの実感としては次の2点が「両方」起きている。

1. アイコンの存在に気づかない（目に入らない）
2. 気づいても、それが押せるボタンか／何を開くのか分からない

## 制約・方針

- **位置は変えない。** ヘッダー右上のまま。既にその場所に慣れている利用者が多いため。
- 変更するのは**デザインのみ**。
- 新しい色は作らず、既存の CSS 変数 `--header-accent` を使う（全7テーマで自然に馴染む）。
- これは `app/` 配下のページ追加・削除ではないため、プライバシーポリシー／利用規約のバージョン更新は不要。

## 採用デザイン（枠線タイプ）

ヘッダー右上のボタンを、ラベル付きの「枠線ピル」に変更する。

- 中身: 時計アイコン（`HiClock`）＋「時計」テキストの横並び。
- 形: 角丸ピル。**枠線と文字色に `--header-accent`** を使い、背景は透明。
- 効果:
  - アクセント色が乗ることで**目に入る**（問題1の解消）。
  - 枠＋「時計」の文字で**押せるボタンだと分かる**（問題2の解消）。
- インタラクション:
  - hover / active 時に背景へ `--header-btn-hover` を薄く敷く。
  - `active:scale-95`（現状の押下挙動を維持）。

ブレストで5パターン（枠線／塗りつぶし／ソフト塗り／二色チップ／縦型コンパクト）を
ビジュアル比較し、**枠線タイプ**を採用した。理由は「目立つが派手すぎず、ヘッダーの
落ち着いた雰囲気を壊さない」ため。

## 変更範囲

- `components/home/HomeHeader.tsx` の `IconButton`（時計ボタン）1か所のみ。
  - アイコン単体から「アイコン＋『時計』ラベル」の枠線ボタンへ変更。
  - `IconButton` のままラベルを内包できない場合は、`Button` または素の要素＋
    既存トークン（`text-header-accent` / `border` / `header-btn-hover`）で実装する。
    既存コンポーネントの使い方は実装時に確認する。
- 遷移先・onClick（`router.push('/clock')`）は変更しない。

## アクセシビリティ

- 可視ラベル「時計」が付くため、`aria-label="デジタル時計を表示"` は維持する。
  - 「時計」は `aria-label` 文字列に含まれるため、WCAG「Label in Name」を満たす。
- `title` は実装時に重複を見て、残すか外すか判断する（必須ではない）。

## テスト

- 既存の `components/home/HomeHeader.test.tsx` を確認・更新する。
  - 「時計」テキストが表示されること。
  - クリックで `/clock` へ遷移すること（既存の検証を踏襲）。

## やらないこと（スコープ外）

- 時計をホームのカード一覧に追加すること（位置変更にあたるため不採用）。
- ライブ時刻表示（案A）、初回コーチマーク（案C）。
- `/clock` ページ側の変更。
