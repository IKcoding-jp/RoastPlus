# 生産記録 v1 仕様書

作成日: 2026-05-29  
対象: RoastPlus ドリップパックコーヒー製造の生産記録  
状態: 本社確認用モック承認済み（2026-05-29）。本社回答とUIモック確定内容を反映した確定版。次工程は実装計画（writing-plans）。

## 1. 目的

RoastPlus に、ドリップパックコーヒー製造の生産実績を「月生産単位」で記録する機能を追加する。

現場スタッフは、作業した日ではなく「何月分として作っているか」を選び、その月生産単位に対して以下を記録する。

- 生豆ハンドピック
- 焙煎
- パッケージ

本社は、RoastPlus から出力した CSV を Excel に取り込み、原価計算や月次確認に使う。

RoastPlus 内では、原価入力・原価計算は行わない。

## 2. 解決する問題

### 困っている人

- 現場スタッフ
- 管理者
- 本社担当者

### 困っていること

- 作業日と製造月が一致しないことがある。
- ハンドピック、焙煎、パッケージの記録が分断される。
- 生豆から最終的に何個のドリップパックになったか追いにくい。
- 本社向けの Excel 原価計算に必要な数字を集めにくい。
- 既存のパッケージ記録だけでは、欠点率や焙煎歩留まりまで追えない。

### RoastPlus で解決すること

- 月生産単位ごとの生産実績を1画面で確認できるようにする。
- 現場の入力先を「生産記録」に一本化する。
- パッケージ記録は生産記録に統合する。
- CSV は本社が必要な月合計に絞る。

### Excel 側に任せること

- 原価入力
- 原価計算
- 仕入れ単価管理
- 包材単価管理
- 詳細な在庫管理
- 月をまたぐ余りの会計処理

## 4. 業務フロー

現場目線の基本フローは以下とする。

1. 生産記録画面を開く。
2. 画面右上で月生産単位を選ぶ。
3. 初回または変更時に「月生産設定」を開く。
4. 生豆総量、豆の種類、配合比率を設定する。
5. 10kg分のハンドピックが終わったら、欠点豆を入力する。
6. 焙煎したら、焙煎前重量と焙煎後重量を入力する。
7. パッケージ後、A班/B班それぞれの良品数・不良品数を入力する。
8. 3列画面で月合計を見る。
9. 本社向けに月合計CSVを出力する。

作業日は入力時の今日の日付を初期値にする。必要な場合は変更できる。

## 5. 月生産単位

月生産単位とは、実際に作業した日ではなく「何月分として製造しているか」を表す単位である。

例:

- 2026年5月29日に作業したが、2026年8月分として記録する。
- この場合、作業日は `2026-05-29`、月生産単位は `2026年8月分` になる。

ロット管理ではなく、月生産単位を v1 の記録単位とする。

## 6. 画面構成

### 基本方針

- iPad 横向きで使いやすいことを優先する。
- 原則1画面で全体が見える。
- 3列構成を基本にする。
- 画面上部中央に見出し `生産記録` を置く。
- 戻るボタンは既存共通コンポーネントを使う。
- 入力はモーダルで行う。
- 保存後はモーダルを閉じ、3列画面に戻る。
- 削除は v1 では出さない。

### 3列画面

左から以下の3列とする。

1. 生豆ハンドピック
2. 焙煎
3. パッケージ

上部に月生産単位の概要を表示する。

例:

```text
月生産単位  配合: ブラジル80% / グアテマラ20%
```

下部に月合計（欠点率・プレミックス袋数・焙煎後重量合計・焙煎ロス率・30kg理論袋数・月良品数・月不良品数・月生産個数・不良率）を表示し、CSV出力ボタンとCSVプレビュー（月合計1行）を置く。色は良品=青、不良=赤、主要操作ボタン=オレンジ。焙煎ロス率（= 1 − 焙煎歩留まり）は月合計サマリーとCSVで表示し、焙煎入力モーダルでは焙煎歩留まりを表示する。

## 7. モーダル仕様

### 共通仕様

- 中央表示のモーダルとする。
- 左上に閉じるボタンを置く。
- 見出しは中央に置く。
- 入力欄は大きめにする。
- 保存ボタンは右下、大きく表示する。
- 戻るボタンは左下に置く。
- 保存後はモーダルを閉じる。
- 完了表示は `保存しました` とする。

### 月生産設定モーダル

入力するもの:

- 生豆総量kg
- 豆の種類
- 配合比率
- 1袋あたり粉量g（既定8.5）

自動表示するもの:

- 対象月（月生産単位で選択済みの値。ここでは変更しない）
- 豆ごとの必要kg
- 配合の合計

ルール:

- 豆は最大4種類。
- 豆名は手入力。
- 比率の合計が100%のとき保存できる。
- 生豆総量は、入力済みのハンドピック進捗より小さくできない。
- 1袋あたり粉量は月単位で固定し、焙煎・パッケージの各記録では変更しない。既定値は8.5g。

### 欠点豆入力モーダル

入力するもの:

- 作業日
- 豆の種類
- 区分
- 今回の生豆重量kg
- 欠点豆重量g

豆の種類:

- 月生産設定で設定した豆から選択する。
- 欠点豆モーダルでは豆名を手入力しない。

区分:

- 前半
- 後半

通常は前半・後半それぞれ10kgで記録する。端数がある場合だけ、今回の生豆重量を変更できる。

表示するもの:

- 保存後の進捗
- 保存後の欠点率

最新記録表示例:

```text
5/11 ブラジル 前半  310g
5/10 グアテマラ 前半  80g
```

### 焙煎入力モーダル

入力するもの:

- 作業日
- 焙煎前重量kg
- 焙煎後重量g

1袋あたり粉量は月生産設定の値を使う。焙煎モーダルでは入力しない。

実装注意: UIモック（app-preview-calculator.html）では粉量を焙煎モーダルに置いていたが、本仕様では月生産設定（月単位固定・既定8.5g）へ移動する。焙煎・パッケージの各モーダルに粉量入力欄を置かないこと。

標準の考え方:

- 生豆1kg分を1単位として記録する。
- 2kg焙煎した日は、1kgずつ分けて記録するとタッパー管理と一致する。
- 焙煎後重量は推定値ではなく実測値とする（業務マニュアル7.2準拠。生豆1kg分ごとに空タッパーで0合わせして計量、約830g前後）。

表示するもの:

- 今回の焙煎歩留まり
- 保存後の焙煎後重量合計
- 当日の理論袋数（焙煎後重量 ÷ 粉量、参考値）

### パッケージ入力モーダル

入力するもの:

- 作業日
- A班 良品数
- A班 不良品数
- B班 良品数
- B班 不良品数

自動計算するもの:

- 良品数 合計
- 不良品数 合計
- 生産個数
- 不良率

文言:

- `成功` ではなく `良品数`
- `失敗` ではなく `不良品数`
- `総数` ではなく `生産個数`
- `失敗率` ではなく `不良率`

色:

- 良品数: 青
- 不良品数: 赤
- 選択中の操作ボタン: オレンジ背景 + 白文字

画面上の3列カードとCSVでは、A班/B班の内訳ではなく合計値を使う。

### 最新2件の編集

各列（生豆ハンドピック / 焙煎 / パッケージ）に最新2件の記録を表示し、その行をタップすると編集できる。

方針（詳細は実装計画で確定）:

- 並び順は作成日時（createdAt）の降順とする。
- 編集は新規入力と同じフォームを使い、値を上書き保存する（削除はv1では出さない）。
- 編集の対象は3列すべて。
- 編集後は当月の全記録を再合算して月合計・進捗を更新する（前月累計を保持しないため矛盾しない）。

### 月生産単位の選択・作成

画面右上のボタンで月生産単位（対象月）を選ぶ。

方針（詳細は実装計画で確定）:

- 既存の月生産単位はリストから選んで切り替える。
- 新規の月生産単位は、対象月を指定して作成する。作成直後に月生産設定モーダルで生豆総量・配合・粉量を入力する。
- 月生産単位が1件もないときは、新規作成を促す初期表示にする。
- 対象月は月生産単位として確定し、月生産設定モーダルでは表示のみとする。

## 9. 計算仕様

単位は保存時に内部で統一する。CSVでは本社が扱いやすい単位で出力する。

### 欠点率

```text
欠点率 = 欠点豆重量合計 ÷ ハンドピック済み生豆重量合計
```

ハンドピック済み生豆重量合計が0（ハンドピック記録が0件）のとき、欠点率は0%表示とする。

例:

```text
620g ÷ 20,000g = 3.1%
```

### 使用可能生豆重量

```text
使用可能生豆重量 = max(0, ハンドピック済み生豆重量合計 - 欠点豆重量合計)
```

欠点豆重量が生豆重量を上回る異常入力でも負値にしない（0でクランプする）。

月全体の想定では、以下も表示できる。

```text
月全体の使用可能生豆重量 = max(0, 生豆総量 - 欠点豆重量合計)
```

ただし、v1画面では必要以上に表示しない。

### プレミックス袋数

プレミックスは生豆の状態で混ぜる。

```text
プレミックス袋数 = floor(使用可能生豆重量 ÷ 500g)
プレミックス余り = 使用可能生豆重量 % 500g
```

表示例:

```text
58袋 + 380g
```

余りは v1 では表示だけで、自動繰越ししない。

### 焙煎前重量

焙煎入力で現場が入力する。

標準は `1.0kg`。

```text
焙煎前重量合計 = 各焙煎記録の焙煎前重量の合計
```

焙煎前重量合計と、ハンドピックの使用可能生豆重量は別系統の値であり、両者の乖離はv1では検証しない（実測のズレを許容する）。

### 焙煎後重量

焙煎入力で現場が入力する。

月合計では以下を表示する。

```text
焙煎後重量合計 = 焙煎後重量の合計
```

### 焙煎ロス率（旧称: 水分蒸発率）

```text
焙煎ロス率 = (焙煎前重量合計 - 焙煎後重量合計) ÷ 焙煎前重量合計
          = 1 - 焙煎歩留まり
```

CSVと月合計サマリーには焙煎歩留まりではなく焙煎ロス率を出力する。焙煎入力モーダルでは焙煎歩留まりを表示し、月合計サマリー・CSVでは `1 - 焙煎歩留まり` の焙煎ロス率へ変換する。両者は補数関係にある。

**2026-05-30 本社決定**: 焙煎後重量はアフターピック（焙煎後の欠点豆除去）後に計測する運用とする。そのため本値は純粋な水分蒸発ではなく「水分蒸発 + アフターピック損失」の合算ロスになり、列名を「水分蒸発率」から「焙煎ロス率」へ改めた。アフターピック専用の入力欄は設けず、本社の予想原価の「③水分蒸発率」と「④アフターピック欠点率」はこの1値（焙煎ロス率）に統合する。

### 焙煎歩留まり

```text
焙煎歩留まり = 焙煎後重量 ÷ 焙煎前重量
```

月合計:

```text
月合計の焙煎歩留まり = 焙煎後重量合計 ÷ 焙煎前重量合計
```

焙煎前重量合計が0（焙煎記録が0件）のとき、焙煎歩留まり・焙煎ロス率はともに0%表示とする。

### 当日理論袋数（参考値）

焙煎入力モーダルで表示する当日の参考値。

```text
当日理論袋数 = floor(焙煎後重量g ÷ 1袋あたり粉量g)
```

1袋あたり粉量が0のときは0袋とする。CSVには出力せず、画面の参考表示のみとする。

### パッケージ生産数

```text
生産個数 = 良品数合計 + 不良品数合計
```

### 良品数

```text
良品数合計 = A班良品数 + B班良品数
```

### 不良品数

```text
不良品数合計 = A班不良品数 + B班不良品数
```

### 不良率

```text
不良率 = 不良品数合計 ÷ 生産個数
```

生産個数が0の場合、不良率は0%表示とする。

### 月累計（パッケージ）

月の各値は、その月（月生産単位）に保存された全パッケージ記録を合算して求める。前月からの繰越しではなく、当月内の合算である。

```text
月良品数   = Σ(当月の全パッケージ記録の良品数合計)
月不良品数 = Σ(当月の全パッケージ記録の不良品数合計)
月生産個数 = 月良品数 + 月不良品数
パッケージロス率 = 月不良品数 ÷ 月生産個数
```

月生産個数が0のとき、パッケージロス率は0%表示とする。

「パッケージロス率」はCSV列名（本社用語）であり、画面表示上の名称は「不良率」を使う。両者は同じ値を指す。

記録を編集した場合も、当月の全記録を再合算するだけで月累計が更新される（前月累計を別途保持しないため、編集と矛盾しない）。同様に、焙煎後重量合計・欠点豆重量合計など他の月合計値も「その月の全記録の合算」であり、前月から引き継ぐ値はない。

### 30kg理論袋数

本社確認の結果、CSVの正式項目として確定した（本社用語）。30,000gの生豆を投入した場合の理論生産パック数で、原価比較の基準値とする。

```text
30kg理論袋数 = floor(
  30,000g
  × (1 - 欠点率)
  × 焙煎歩留まり
  ÷ 1袋あたり粉量g
)
```

確定事項:

- 基準は常に **30,000g 固定** とする。月生産設定の生豆総量の入力値には依存しない。"30kg基準の理論値" として一貫させ、月をまたいだ生産効率の比較を可能にする。
- 欠点率・焙煎歩留まりは当月の月合計値を使う。
- 1袋あたり粉量は月生産設定の値（既定8.5g）を使う。
- 小数は切り捨て（floor）。
- この値は原価計算ではなく、生産見込み・効率の参考値とする。本社はExcel側で原価計算に利用する。

実装注意:

- UIモック（app-preview-calculator.html）の現行実装は `使用可能生豆g × 焙煎歩留まり ÷ 粉量`（使用可能生豆g = max(0, 生豆総量g − 欠点豆g)）と、欠点豆を**絶対量で減算**する生豆総量ベースになっている。本式は当月実績から求めた**欠点率を30,000gに掛ける比率ベース**で、計算の意味が異なる。両者が一致するのは「生豆総量=30,000g かつ ハンドピック完了（ハンドピック済み合計=30,000g）」のときのみ。モックの減算ロジックをそのまま流用せず、実装では **30,000g固定式に統一** すること。
- 欠点率または焙煎歩留まりが算出できない（分母0）とき、および1袋あたり粉量が0のときは、30kg理論袋数を0袋とする。

### 入力バリデーション

各入力欄の基本ルール。詳細なエラー表示方法は実装計画（writing-plans）で確定する。

| 入力項目                      | 必須 | 範囲                                      | 型     |
| ----------------------------- | ---- | ----------------------------------------- | ------ |
| 生豆総量kg                    | 必須 | 0より大。ハンドピック済み生豆重量合計以上 | 小数可 |
| 1袋あたり粉量g                | 必須 | 0より大（既定8.5）                        | 小数可 |
| 配合比率%                     | 必須 | 各0以上、合計100%                         | 整数   |
| 今回の生豆重量kg              | 必須 | 0より大（通常10）                         | 小数可 |
| 欠点豆重量g                   | 必須 | 0以上（小数入力は四捨五入）               | 整数   |
| 焙煎前重量kg / 焙煎後重量g    | 必須 | 0より大。焙煎後 ≤ 焙煎前                  | 小数可 |
| 良品数 / 不良品数（A班・B班） | 必須 | 0以上の整数                               | 整数   |

共通ルール:

- 空欄・負値・非数値は保存不可とする。
- 1袋あたり粉量は必ず0より大（0除算を物理的に防ぐ）。
- 配合比率の合計が100%でないときは保存ボタンを無効化する（許容誤差なし、整数で入力）。
- 月生産設定の生豆総量は、すでに入力済みのハンドピック済み生豆重量合計を下回る値には変更できない（保存ボタン無効化）。
- 異常入力に備え、使用可能生豆重量は `max(0, …)` でクランプする。

### 表示規則（丸め）

画面表示・CSV出力ともに以下で統一する。

- 割合（欠点率・焙煎ロス率・不良率／パッケージロス率・焙煎歩留まり）: 小数第1位まで（四捨五入）。例: `3.1%`。
- 重量（生豆重量kg・焙煎後重量kg）: 小数第2位まで。例: `20.10kg`。欠点豆重量gは整数。
- 袋数（30kg理論袋数・当日理論袋数・プレミックス袋数）: 整数（floor、切り捨て）。
- 個数（良品数・不良品数・生産個数）: 整数。
- 内部保存は単位をgに統一し、CSV出力時に上記の単位・桁へ変換する。

## 10. CSV仕様

CSV は本社が Excel に取り込むための月合計CSVを主とする。

v1では明細CSVを出さない。

CSVは、その月（月生産単位）の生産が一通り終わってから本社へ出力する運用とする。月の途中でも出力はできるが、その時点ではハンドピック進捗などが未完了のため暫定値になる。月の生産が完了すると、生豆重量kg（生豆総量）と欠点率の母数（ハンドピック済み生豆重量合計）が一致するため、本社のExcel検算とも整合する。

### 月合計CSVの項目（本社確定）

本社承認の12項目を、以下の順序で出力する（UIモック app-preview-calculator.html のCSV生成順と完全一致）。

| #   | 列名             | 単位 | 元になる値                                         |
| --- | ---------------- | ---- | -------------------------------------------------- |
| 1   | 対象月           | -    | 月生産単位（例: 2026年8月分）                      |
| 2   | 配合             | -    | 1列にまとめる（例: ブラジル 80% / グアテマラ 20%） |
| 3   | 生豆重量kg       | kg   | 生豆総量                                           |
| 4   | 欠点豆重量g      | g    | 欠点豆重量合計                                     |
| 5   | 欠点率           | %    | 欠点豆重量合計 ÷ ハンドピック済み生豆重量合計      |
| 6   | 焙煎後重量kg     | kg   | 焙煎後重量合計                                     |
| 7   | 焙煎ロス率       | %    | 1 − 焙煎歩留まり（水分蒸発 + アフターピック損失）  |
| 8   | 30kg理論袋数     | 袋   | 30,000g固定式（第9章参照）                         |
| 9   | 月良品数         | 個   | 累積方式（第9章参照）                              |
| 10  | 月不良品数       | 個   | 累積方式                                           |
| 11  | 月生産個数       | 個   | 月良品数 + 月不良品数                              |
| 12  | パッケージロス率 | %    | 月不良品数 ÷ 月生産個数（画面表示は「不良率」）    |

配合は1列にまとめる。

例:

```text
ブラジル 80% / グアテマラ 20%
```

A班/B班の内訳は CSV に出さない。CSVでは合計値だけを出す。

生豆重量kg（列3）は月生産設定の生豆総量、欠点率（列5）の母数はハンドピック済み生豆重量合計で、計算上は別の値である。月の生産完了後（ハンドピック完了後）は両者が一致するため、本社が `列4 ÷ 列3` で欠点率を概算しても列5とほぼ一致する。

旧仕様にあった「プレミックス袋数 / 焙煎前重量 / 焙煎歩留まり」はCSVには出力しない（画面表示には残す）。本社が必要とするのは上記12項目に確定。原価（1袋あたり原価など）は本社がExcel側で計算し、その分母には「月良品数」を使う（本社確定）。

### CSVに入れないもの

- 原価
- 単価
- 包材コスト
- 管理者確認メモ
- アフターピック
- 詳細な作業メモ
- 旧パッケージ記録のA班/B班内訳

## 13. Firestoreデータ構造案

本項目は実装前の案であり、実装計画（writing-plans）で最終化する。

想定:

```text
users/{uid}/productionRecords/{yyyy-MM}
users/{uid}/productionRecords/{yyyy-MM}/handpickEntries/{entryId}
users/{uid}/productionRecords/{yyyy-MM}/roastEntries/{entryId}
users/{uid}/productionRecords/{yyyy-MM}/packageEntries/{entryId}
```

ドキュメントID `{yyyy-MM}` は対象月（月生産単位）を表す（作業日ではない）。`month` フィールドの正規形式も `yyyy-MM`（例: `2026-08`）とし、画面表示の「2026年8月分」はそこから導出する。最新2件・月累計の取得はこのキーを基準に行う。

```ts
interface ProductionRecordMonth {
  month: string;
  greenBeanTotalGram: number;
  powderPerPackGram: number; // 1袋あたり粉量。既定8.5。月単位で固定。
  blendItems: Array<{
    beanName: string;
    ratioPercent: number;
  }>;
  createdAt: Timestamp;
  updatedAt: Timestamp;
}
```

interface HandpickEntry {

### 残課題（実装前または運用で確認）

- 現場スタッフの入力項目の過不足 → 本社は「大丈夫だが、スタッフの意見も聞くのが良い」とコメント。実装前にスタッフ確認を推奨。
