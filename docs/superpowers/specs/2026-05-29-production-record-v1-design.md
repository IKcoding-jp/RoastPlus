# 生産記録 v1 仕様書

作成日: 2026-05-29  
対象: RoastPlus ドリップパックコーヒー製造の生産記録  
状態: 実装前の仕様整理。本社確認用の計算モック作成を次工程とする。

## 1. 目的

RoastPlus に、ドリップパックコーヒー製造の生産実績を「月生産単位」で記録する機能を追加する。

現場スタッフは、作業した日ではなく「何月分として作っているか」を選び、その月生産単位に対して以下を記録する。

- 生豆ハンドピック
- 焙煎
- パッケージ

本社は、RoastPlus から出力した CSV を Excel に取り込み、原価計算や月次確認に使う。

RoastPlus 内では、原価入力・原価計算は行わない。

## 2. 解決する問題

### 困っている人

- 現場スタッフ
- 管理者
- 本社担当者

### 困っていること

- 作業日と製造月が一致しないことがある。
- ハンドピック、焙煎、パッケージの記録が分断される。
- 生豆から最終的に何個のドリップパックになったか追いにくい。
- 本社向けの Excel 原価計算に必要な数字を集めにくい。
- 既存のパッケージ記録だけでは、欠点豆率や焙煎歩留まりまで追えない。

### RoastPlus で解決すること

- 月生産単位ごとの生産実績を1画面で確認できるようにする。
- 現場の入力先を「生産記録」に一本化する。
- パッケージ記録は生産記録に統合する。
- CSV は本社が必要な月合計に絞る。

### Excel 側に任せること

- 原価入力
- 原価計算
- 仕入れ単価管理
- 包材単価管理
- 詳細な在庫管理
- 月をまたぐ余りの会計処理

## 4. 業務フロー

現場目線の基本フローは以下とする。

1. 生産記録画面を開く。
2. 画面右上で月生産単位を選ぶ。
3. 初回または変更時に「月生産設定」を開く。
4. 生豆総量、豆の種類、配合比率を設定する。
5. 10kg分のハンドピックが終わったら、欠点豆を入力する。
6. 焙煎したら、焙煎前重量と焙煎後重量を入力する。
7. パッケージ後、A班/B班それぞれの良品数・不良品数を入力する。
8. 3列画面で月合計を見る。
9. 本社向けに月合計CSVを出力する。

作業日は入力時の今日の日付を初期値にする。必要な場合は変更できる。

## 5. 月生産単位

月生産単位とは、実際に作業した日ではなく「何月分として製造しているか」を表す単位である。

例:

- 2026年5月29日に作業したが、2026年8月分として記録する。
- この場合、作業日は `2026-05-29`、月生産単位は `2026年8月分` になる。

ロット管理ではなく、月生産単位を v1 の記録単位とする。

## 6. 画面構成

### 基本方針

- iPad 横向きで使いやすいことを優先する。
- 原則1画面で全体が見える。
- 3列構成を基本にする。
- 画面上部中央に見出し `生産記録` を置く。
- 戻るボタンは既存共通コンポーネントを使う。
- 入力はモーダルで行う。
- 保存後はモーダルを閉じ、3列画面に戻る。
- 削除は v1 では出さない。

### 3列画面

左から以下の3列とする。

1. 生豆ハンドピック
2. 焙煎
3. パッケージ

上部に月生産単位の概要を表示する。

例:

```text
月生産単位  配合: ブラジル80% / グアテマラ20%
```

下部に月合計を表示し、CSV出力ボタンを置く。

## 7. モーダル仕様

### 共通仕様

- 中央表示のモーダルとする。
- 左上に閉じるボタンを置く。
- 見出しは中央に置く。
- 入力欄は大きめにする。
- 保存ボタンは右下、大きく表示する。
- 戻るボタンは左下に置く。
- 保存後はモーダルを閉じる。
- 完了表示は `保存しました` とする。

### 月生産設定モーダル

入力するもの:

- 対象月
- 生豆総量kg
- 豆の種類
- 配合比率

自動表示するもの:

- 豆ごとの必要kg
- 配合の合計

ルール:

- 豆は最大4種類。
- 豆名は手入力。
- 比率の合計が100%のとき保存できる。
- 生豆総量は、入力済みのハンドピック進捗より小さくできない。

### 欠点豆入力モーダル

入力するもの:

- 作業日
- 豆の種類
- 区分
- 今回の生豆重量kg
- 欠点豆重量g

豆の種類:

- 月生産設定で設定した豆から選択する。
- 欠点豆モーダルでは豆名を手入力しない。

区分:

- 前半
- 後半

通常は前半・後半それぞれ10kgで記録する。端数がある場合だけ、今回の生豆重量を変更できる。

表示するもの:

- 保存後の進捗
- 保存後の欠点率

最新記録表示例:

```text
5/11 ブラジル 前半  310g
5/10 グアテマラ 前半  80g
```

### 焙煎入力モーダル

入力するもの:

- 作業日
- 焙煎前重量kg
- 焙煎後重量kg

標準の考え方:

- 生豆1kg分を1単位として記録する。
- 2kg焙煎した日は、1kgずつ分けて記録するとタッパー管理と一致する。

表示するもの:

- 今回の歩留まり
- 保存後の焙煎後合計

### パッケージ入力モーダル

入力するもの:

- 作業日
- A班 良品数
- A班 不良品数
- B班 良品数
- B班 不良品数

自動計算するもの:

- 良品数 合計
- 不良品数 合計
- 生産個数
- 不良率

文言:

- `成功` ではなく `良品数`
- `失敗` ではなく `不良品数`
- `総数` ではなく `生産個数`
- `失敗率` ではなく `不良率`

色:

- 良品数: 青
- 不良品数: 赤
- 選択中の操作ボタン: オレンジ背景 + 白文字

画面上の3列カードとCSVでは、A班/B班の内訳ではなく合計値を使う。

## 9. 計算仕様

単位は保存時に内部で統一する。CSVでは本社が扱いやすい単位で出力する。

### 欠点豆率

```text
欠点豆率 = 欠点豆重量合計 ÷ ハンドピック済み生豆重量合計
```

例:

```text
620g ÷ 20,000g = 3.1%
```

### 使用可能生豆重量

```text
使用可能生豆重量 = ハンドピック済み生豆重量合計 - 欠点豆重量合計
```

月全体の想定では、以下も表示できる。

```text
月全体の使用可能生豆重量 = 生豆総量 - 欠点豆重量合計
```

ただし、v1画面では必要以上に表示しない。

### プレミックス袋数

プレミックスは生豆の状態で混ぜる。

```text
プレミックス袋数 = floor(使用可能生豆重量 ÷ 500g)
プレミックス余り = 使用可能生豆重量 % 500g
```

表示例:

```text
58袋 + 380g
```

余りは v1 では表示だけで、自動繰越ししない。

### 焙煎前重量

焙煎入力で現場が入力する。

標準は `1.0kg`。

### 焙煎後重量

焙煎入力で現場が入力する。

月合計では以下を表示する。

```text
焙煎後重量合計 = 焙煎後重量の合計
```

### 水分蒸発率

```text
水分蒸発率 = (焙煎前重量 - 焙煎後重量) ÷ 焙煎前重量
```

### 焙煎歩留まり

```text
焙煎歩留まり = 焙煎後重量 ÷ 焙煎前重量
```

月合計:

```text
月合計の焙煎歩留まり = 焙煎後重量合計 ÷ 焙煎前重量合計
```

### パッケージ生産数

```text
生産個数 = 良品数合計 + 不良品数合計
```

### 良品数

```text
良品数合計 = A班良品数 + B班良品数
```

### 不良品数

```text
不良品数合計 = A班不良品数 + B班不良品数
```

### 不良率

```text
不良率 = 不良品数合計 ÷ 生産個数
```

生産個数が0の場合、不良率は0%表示とする。

### 30kg換算の想定生産数

v1 の画面上では強く出さない。本社確認用の計算モックでは参考値として扱える。

仮式:

```text
30kg換算の想定生産数 =
  30,000g
  × (1 - 欠点豆率)
  × 焙煎歩留まり
  ÷ 1パック粉量g
```

1パック粉量は現行 `8.5g` を仮値とする。

この値は原価計算ではなく、生産見込みの参考値とする。

## 11. 既存パッケージ記録との統合方針

既存のパッケージ記録は、生産記録に統合する。

方針:

- 旧「パッケージ記録」画面は削除対象。
- 旧「パッケージ記録 月次集計」画面も削除対象。
- 本社向けCSVは、新しい生産記録CSVに一本化する。
- 現時点で旧パッケージ記録に過去データは入っていない前提。
- 旧データ移行スクリプトは v1 では不要。

ここでいう移行は、過去データ移行ではなく、機能の移行である。
