# Design: Issue #434 パッケージ数記録機能を追加する

## 方針

作業日単位で1つのパッケージ数記録を保存し、A班・B班それぞれの成功数/失敗数から合計値を計算して表示する。
複数端末で同じ日の記録を扱うため、Firestoreのリアルタイム購読を前提に設計する。

今日以前の日付は入力・修正を許可し、削除は当日分のみ許可する。
未来日の保存はクライアント側で防ぐ。

## 変更対象候補

- `app/` - パッケージ数記録画面、または既存画面への導線追加
- `components/` - 入力フォーム、合計表示、過去日一覧
- `components/ui/` - 既存の共通UIコンポーネントを利用
- `hooks/` - 記録の購読・保存状態管理が必要な場合に追加
- `lib/firestore/` - パッケージ数記録のCRUD/購読処理
- `types/` - パッケージ数記録の型定義
- `firestore.rules` - 共有データ・未来日保存制限を実装する場合に更新

## データ設計の検討メモ

実装前に、少なくとも以下を決める。

- 作業日をドキュメントIDにするか
- チーム共有データとして保存するか、ユーザー配下に保存するか
- A班用/B班用iPadが同じ記録を読み書きするための認可方針
- 削除は当日分のみ物理削除として扱う
- 当日判定のタイムゾーン

## 影響範囲

- パッケージ数の記録画面
- Firestore保存データ
- 複数端末での同期表示
- 認証済みユーザーの読み書き範囲
- 過去日データの追加・修正

## リスク

- 共有データとして保存する場合、既存のowner isolation方針との整合確認が必要
- クライアント側だけで未来日保存を禁止すると、直接書き込みを防げない可能性がある
- 当日判定のタイムゾーンが曖昧だと、日付をまたぐ時間帯に編集可否がずれる
- 同時入力時の上書き競合をどう扱うかを実装前に決める必要がある
